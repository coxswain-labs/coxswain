  - {{ include "coxswain.controller.fullname" . }} (leader-elected status writer)

  curl http://localhost:{{ .Values.health.port }}/readyz

{{- if .Values.security.rootless }}

Rootless mode is enabled: the shared-proxy container binds 8080/8443 and the
gateway Service maps 80/443 → 8080/8443. CAP_NET_BIND_SERVICE is not required.
{{- end }}

{{- if .Values.networkPolicy.enabled }}

The controller's operator port ({{ .Values.operator.port }}) is fenced by a
NetworkPolicy: only pods in the same namespace may reach it. That port serves
Kubernetes manifests and pod logs, so this keeps it away from other tenants.
Proxy and relay pods do not bind it at all. Everything else — the data plane,
probes, discovery — is unaffected, and `kubectl port-forward` still works.
{{- if .Values.networkPolicy.telemetry.fenced }}

networkPolicy.telemetry.fenced is on, so /metrics and /statusz are restricted to
the pod's own namespace and {{ include "coxswain.namespace" . }}. The PodMonitor
scrapes pod IPs directly, so a Prometheus in any other namespace is DROPPED
SILENTLY — add its namespace to `networkPolicy.telemetry.extraIngress` or its
targets will sit at "context deadline exceeded" with nothing logged.
{{- else }}

/metrics and /statusz are reachable from any namespace, so Prometheus scrapes
without further configuration. Set `networkPolicy.telemetry.fenced: true` to
restrict them — the metric labels enumerate route and backend names, which is
worth closing when untrusted workloads share the pod network.
{{- end }}

If your CNI does not enforce NetworkPolicy the object is inert; set
`networkPolicy.enabled: false` to omit it.
{{- else }}

WARNING: networkPolicy.enabled is false, so the operator port
({{ .Values.operator.port }}) is reachable from every pod in the cluster. It
serves verbatim Kubernetes manifests (including Pod environment variables) and
pod logs. Fence it with your own NetworkPolicy, or set
`operatorAuth.secretName`.
{{- end }}
{{- if .Values.operatorAuth.secretName }}

The controller's operator port requires HTTP Basic auth from Secret
"{{ .Values.operatorAuth.secretName }}" (key `auth`, one bcrypt htpasswd line).
Every path on that port is covered, with no exemptions. Prometheus is
unaffected: /metrics lives on the telemetry port, which is never authenticated.
If the Secret is missing or unusable the operator surface returns 503:

  kubectl -n {{ include "coxswain.namespace" . }} get secret {{ .Values.operatorAuth.secretName }}
{{- end }}

The shared-proxy ServiceAccount holds no Kubernetes API access — it exists
only as a pod identity for mTLS bootstrap. Verify no coxswain RBAC is bound:

  kubectl auth can-i --list --as=system:serviceaccount:{{ include "coxswain.namespace" . }}:{{ include "coxswain.sharedProxy.fullname" . }}

The output should show only Kubernetes baseline grants (selfsubject* resources
and non-resource URLs). If you see any resource rows beyond those, file a bug.
